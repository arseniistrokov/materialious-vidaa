# Materialious для VIDAA 9 — экспериментальная сборка

Основа: Materialious 1.18.9, commit b08caf2310cea7340f897c5576795984b02e63b8.
Оригинал: https://github.com/Materialious/Materialious
Лицензия: AGPL-3.0. Оригинальные LICENSE, README, благодарности авторам и зависимости сохранены.
Изменения VIDAA подготовлены 2026-10-18. Это не официальный продукт Materialious, Hisense или Google.

## Что меняется

Используются исходные API, stores, IndexedDB, история, подписки, SponsorBlock,
Shaka/SABR, настройки качества/скорости/языков, фильтры, импорт/экспорт и маршруты Materialious.
Новая бизнес-логика YouTube с нуля не создаётся.

TV-представление отделено от Android-платформы: isTvInterface() включает существующие TV-компоненты
на VIDAA, но Capacitor остаётся web и ограничения прямого извлечения потоков не отключаются.
Тёмный интерфейс, левое меню, сетка 3 карточки на 1920×1080, видимый фокус,
пульт Hisense, экранная RU/EN-клавиатура для исходных полей, исходный TV-плеер и рекомендации.
Исходные компоненты качества/субтитров показаны и в TV-режиме.
Буфер Shaka на VIDAA уменьшен до 30 с вперёд/назад; остальные платформы сохраняют исходные значения.
Клавиши: стрелки, OK, Back (461/10009), media play/pause/stop/seek.
Не каждое поведение физического пульта уже проверено: требуется аппаратный тест.

`?ui=original` в начальном URL отключает VIDAA-оформление для сравнения с исходным интерфейсом.
Языковая совместимость Promise.withResolvers добавляется до загрузки приложения и не заменяет native-реализацию.

## Сборка без Android/Electron и серверного runtime

Node.js 24 LTS. Из папки materialious:

```
npm ci --ignore-scripts --no-audit --no-fund
npm run patch:shaka
npm run build:vidaa
```

build:vidaa включает TV UI, цель chrome111, base /materialious-vidaa и adapter-static.
Не собирает APK, Electron и не запускает сервер. Установка с --ignore-scripts исключает
ненужные загрузки native runtime; проверенный patch:shaka запускается отдельно.
Результат — materialious/build. Для другого адреса установите VIDAA_BASE_PATH до сборки.
GitHub Pages требует .nojekyll (каталог _app) и SPA-fallback 404.html.

Исходники этой модификации должны предоставляться вместе с опубликованной сборкой.
Страница диагностики содержит ссылки на соответствующий source.zip и LICENSE.txt.
Общий план и карта компонентов: VIDAA-PLAN.md.

## Воспроизведение и code 4

Отдельный маршрут /vidaa: 4 синтетических 24-секундных MP4 того же origin,
сравнение native HTML5 и исходного Shaka. Baseline L3.0 / Main L3.1, yuv420p,
AAC-LC mono 44.1 kHz / stereo 48 kHz; четвёртый тест без звука.
Все moov до mdat (faststart). Отчёт: MediaError.message/code, currentSrc,
readyState, networkState, canPlayType, buffered/seekable, события и HTTP/Range.
Отчёт не отправляется автоматически в сеть; параметры signed URL скрываются.

W3C Sintel: H264 High L3.0, AAC-LC stereo48, moov после mdat.
Это отличия от контролей, но они НЕ доказывают причину отказа VIDAA.
На Windows/Chrome155 оба движка декодировали все четыре файла; WebAudio подтвердил
ненулевой PCM в A/B/C и отсутствие PCM в D; проверены пауза, ±10 с, продолжение.
Это НЕ подтверждение исправления code 4 на телевизоре.

## Ограничения статического хостинга

GitHub Pages раздаёт интерфейс; он не выполняет /api/proxy, /api/poToken,
базу аккаунтов, серверные загрузки, watch party и другие серверные функции.
Код этих функций сохранён, но для работы нужен совместимый удалённый backend.
Статический режим исходного проекта требует Invidious/Companion с рабочим API и CORS.
Удаление native/server проверок ради фиктивного YouTube fallback не производится.

Проверки публичных сервисов с текущего ПК: invidious.materialio.us/api/v1/videos/... → 500,
materialio.us/api/config → 404. Ранее три других Invidious API ответили 401/403.
Рабочий источник YouTube-потоков ещё не подтверждён. Авторизация Google не выполняется.
Автономная работа без ПК означает GitHub Pages плюс доступный внешний сервис потоков,
а не исполнение сервера Node.js внутри телевизора.

## Телевизор

Существующий VIDAA Video Probe и его URL не заменяются.
Новая сборка не регистрируется через Sidee и не запускается на ТВ автоматически.
Нужны отдельное разрешение владельца на новую плитку/изменение плитки и ручная проверка.
Фактический UA от владельца: Chrome/111.0.5563.146, VIDAA-MT9602.
Полная аппаратная совместимость, звук и реклама ещё не подтверждены.

Дополнительный контроль E: адаптивный DASH 360p/720p с тем же синтетическим видеорядом.
С исходным TV Player подтверждено реальное переключение декодируемого разрешения через оригинальное меню качества.
